# BVE Map Editor

BVE Trainsim 5 / 6 向けのBVE Map構文（`BveTs Map 2.02`）専用・高機能テキストエディタです。
リアルタイム構文エラーチェック、自動補完（IntelliSense）、BVE直連デバッグ機能、大規模ファイル対応（AvalonEdit）を備え、安全かつ快適なマップ制作環境を提供します。

---

## 🌟 主な特徴

- **高性能なコードエディタ（AvalonEdit）**
  - 数十万行クラスの大規模マップファイル（67万文字等）でも軽量・軽快に動作（行の仮想化表示）。
  - BVE Map構文に特化したカスタムシンタックスハイライト（コメント、数値、文字列、キーワードの色分け）。
  - 水平スクロールバーは常に表示（「右端で折り返す」のときは非表示）。
  - 検索と置換（Ctrl+F で開く。すでに開いていれば前に出して今のタブを検索。開いたままタブを切り替えても、切り替えた先のタブを検索。閉じるとメインウィンドウが前に出る。開いたままでもアプリを終了できる（終了するときに一緒に閉じる）。検索欄で Enter を押すと「次を検索」）。名前を付けて保存は Ctrl+Shift+S。
  - Ctrl＋マウスホイールで文字の拡大・縮小（マウスの下にある文字を中心に拡大・縮小）。
  - フォント・右端で折り返す・テーマ（ダーク／ライト）・文字の大きさは、開いている全部のタブと新しく開くタブに効く。
  - 書き換えても、元に戻して開いた（保存した）時点の内容と同じになれば「変更なし」に戻る（タイトルの * が消え、閉じるときの警告も出ない）。
- **リアルタイム構文エラー検出（別プロセス解析）**
  - 入力に追従してバックグラウンドで構文解析（`BveMapParserWorker`）を実行。UIスレッドをフリーズさせません。ファイルを保存したとき・別のソフトからエディタに戻ったときも調べ直す（リストファイルや include 先の変更を反映）。タブで開いているリストファイルは保存前の内容でキーを読む。構文チェックが 60 秒以内に終わらないときは、ワーカーを自動で起動し直す。リストファイル（CSV）など、マップでないファイルのタブを見ているときは、そのファイルをマップとして調べず、最後に調べたマップを調べ直す（CSV を直すとすぐマップのエラーに反映される）。
  - include を多用する大きなマップでも、変数入りの距離程（例: `1320 + $WK02;`）を高速に計算して解析時間を短縮。
  - エラーは赤、警告はオレンジの波線でエディタ上に表示（今のタブのファイルのエラーのみ）。キー・ファイルパス・コマンド名など、間違っている部分だけに波線を引く。重なった部分はエラーを優先。
  - 下部の「構文エラー一覧」ダブルクリックで該当行・列へ即座にカーソルジャンプ。
  - エラーコンテキストメニューから行コピー、すべてコピー（見出し付きのタブ区切り。Excel・メモ帳に貼れる）、Web検索、Gemini相談をサポート。「このエラーについて検索・ヘルプを表示」では、エラーの種類ごとの解説ページ（原因・直し方・例・修正の候補）を開く（Help フォルダ）。
  - エラー一覧のエラー、またはエディタのエラーのある行を右クリック ➔「修正の候補」で、簡単なエラーをその場で直せる（`;` 抜け、`;` の連続、`()` 抜け、`.` 抜け、全角英数・記号・全角スペース）。未知のコマンドやリストにないキーは、つづりの近い名前を最大3つ候補に出す（例: `Structre` → `Structure`）。コマンド名の候補は引数の数が合うものだけ（例: 引数3個なら `Put0`、9個なら `Put`）。`Structure['a']Put(` のような `.` 抜けも直せる。`.` のない単語も似た名前を候補に出す（`includ` → `include`、`Curvee` → `Curve`）。閉じる `'` の足し忘れ（`include 'a.txt;`、`Begin0('RoadR, 1, ...`）も直せる。引数の数が合わないときは、数が合う兄弟のコマンドに変える候補を出す（例: 引数3個の `Put` → `Put0`、引数9個の `Put0` → `Put`）。足りない引数を後ろに足す（数値は `0`、文字列は `''`）・多い引数を後ろから消す候補も出す（Repeater は除く）。`'BeginTransition' is required before 'Begin'` のときは、ダイアログで距離程を選んで BeginTransition の行を足せる。必須の Load がないときは Load の行（Sound.Load は Station.Load より前）、`Cant.SetGauge` がないときは SetGauge の行（1.067 / 1.435）を足す候補も出す。Ctrl+Z で元に戻せる（保存はしない）。同じファイルの同じ種類のエラー（`;` 抜け・全角文字など）は「まとめて直す」で一度に直せる。
- **高度なBVE構文検証（`MapParser`）**
  - ヘッダー検証（`BveTs Map 2.02`）、重複ヘッダー検出。
  - 必須構文（`Station.Load`等）の記述順序・距離程（`0;`）前後の配置チェック。
  - 括弧の不整合（`()`, `[]`）、引用符抜け、文末セミコロン忘れ（カッコが閉じている文が対象。`+` などで次の行に続く文は1つの文として扱う。1行に2つの文があって間の `;` が抜けているときも検出）、全角・マルチバイト文字混入検出（続いている全角文字は1件にまとめる）。
  - 各種参照CSVリスト（ストラクチャー・サウンド・ステーション）のキー存在照合。リストファイルは UTF-8 / Shift-JIS のどちらでも読める（日本語のキーにも対応）。
  - `include 'ファイル名.txt';` のインクルード先ファイルの中身もチェック（書き方・ファイルの有無・循環インクルード）。BOM付きのインクルード先にも対応。
  - 読み込むファイル（インクルード先・リストファイル・他列車ファイル）は 20MB まで（大きすぎるファイルはエラーにして読まない）。
  - インクルード先をタブで開いて編集中なら、保存前の内容でチェック。インクルード先のタブでは親ファイルからたどってチェック（親ファイルを一度チェックした後）。
  - インクルード先に書いた Load（リストファイル）も読み込み、インクルード先のキーもチェックする（キーの補完にも入る）。計算式のキーは調べない。
  - 変数（`$変数名`）構文対応および各種誤用判定（`$`抜け、複数代入、引数内代入など）。その行より前で値を入れていない変数を使うとエラー（`$abc;` や `Curve.SetGauge($g);` など）。`$` の後ろに名前がない（`$;` や `100$;`）ときもエラー。距離程や代入の右辺で、値と値の間に演算子がない（`$a $a;` や `100 200;`）ときもエラー。同じ変数をもう一度宣言すると警告（BVE ではエラーにならず後の値が使われる）。変数を使った距離程（`$a + 50;` など）も、数字だけの距離程と同じチェックをする。変数を使った文でも「軌間を設定した」「BeginTransition をした」は記録する。
  - キー `[]` 抜け（例: `Track.Cant.SetGauge(1);`）や丸括弧 `()` 抜け（例: `Track['A'].Cant.SetGauge;`）の検出。
  - キーの `'` 抜け（例: `Structure['FormR0]`、`Structure[FormR0]`）や、キーを `( )` で書いた間違い（例: `Structure('FormR0')`）の検出。修正の候補で `'FormR0'` に直せる。
  - 計算式の括弧が深すぎる（64 段を超える）ときはエラーにして計算しない（ワーカーが落ちるのを防ぐ）。
  - 距離程の式が演算子で終わっている（例: `distance +;`）の検出。修正の候補で演算子を消せる。`+` で終わる行の次の行がコマンド（`Curve.Begin` など）で始まるときは、別の文として読む。
  - 文字列の引数の `' '` 忘れ（例: `Structure['abc'].Put(xyz, 0, ...)`）の検出。修正の候補で `'xyz'` に直せる。
- **インテリジェントな自動補完（IntelliSense）**
  - BVE構文コマンドやパラメータの入力補完（`BveSyntaxProvider`）。
  - キーの入力補完: `Structure['` / `Sound['` / `Sound3D['` / `Station['` / `Signal['` / `Train['` と打つと、読み込んだリストファイルのキーを候補に表示（構文チェックが一度終わった後）。`Repeater['…'].Begin(` の11番目以降・`Begin0(` の5番目以降の引数で `'` を打つと、ストラクチャーのキーを候補に表示。キーを選ぶと閉じる `']` も自動で入り、続けて `.Put();` などの関数を候補に表示（選ぶとカーソルが `(` と `)` の間へ）。Repeater の引数では閉じる `'` だけ。`Structure['']` のようにキーが空の引用符の間にカーソルを置いても候補を表示（Repeater は除く）。キーの候補は入力した文字で始まるものだけに絞り込む。`Repeater['abc']` のように `]` まで打つと `.Begin();` / `.Begin0();` / `.End();` などの関数を候補に表示（括弧の自動補完で入った `]` の直前で `]` を打つと、二重にならずに進む）。
  - `$変数` にマウスを乗せると、宣言（例: `$abc = 1234　（Map.txt の 27 行目）`）を吹き出しで表示（構文チェックが一度終わった後。include 先の宣言も出る。何回か宣言していれば全部出す）。吹き出しの文字の大きさはエディタと同じ（Ctrl＋ホイールで変わる）。「設定」➔「変数の宣言を吹き出しで表示する」でオン・オフ（初期値はオン）。
  - 候補が出ているときに記号（`[` `(` `'` `;` など）を打っても、候補は確定せずに閉じる（確定は Enter / Tab）。「設定」➔「キーの自動補完を有効にする」でオン・オフ（「自動補完」とは別）。
  - スペースキー・数値入力時の誤発火防止ガード。
- **デバッグ & ツール連携**
  - エディタのメニューから BVE 5 / 6 本体や QuickMapViewer を起動できる（マップのファイルは渡さないので、開くマップ・シナリオは起動したソフトで選ぶ。BVE はファイルを読むので、試す前にエディタで保存しておく）。
  - 実行ファイルパスの自動保存・オープンダイアログでのフォールバック。
- **文字コード**
  - 開くときに文字コード（UTF-8 / UTF-8 BOM付き / Shift-JIS など）をファイル全体から自動判定。BOM は本文に含めず、保存時に付け直す。
  - 保存時に UTF-8（BOMなし）/ UTF-8（BOM付き）/ Shift-JIS を選択可能。ダイアログで「このファイルは次回から確認しない」にチェックすると、そのファイルの選択（BOMの有無を含む）を記憶し、次回から確認なしで上書き保存（詳細設定の「特定ファイルの設定をリセット」で解除）。
  - 選んだ文字コード（Shift-JIS など）で保存できない文字があるときは、保存前に行番号つきで知らせ、UTF-8 に変えて保存するかを選べる。
  - 保存したときはメッセージの窓を出さず、ステータスバーに「保存しました: ファイル名（時刻）」と出す。
  - 文字コードはタブごとに管理（タブを切り替えるとステータスバーの文字コード表示も切り替わる）。
- **プロジェクト & ワークスペース管理**
  - エクスプローラーペイン（ファイルツリー）と複数タブ編集。新規作成で「無題」のタブを追加。ファイルは新しいタブで開く（空の「無題」タブだけはそのタブに読み込む）。
  - タブ名の × ボタン、またはマウスの真ん中ボタンでタブを閉じる（未保存なら保存するか聞く）。タブ名を右クリックすると「閉じる」「ほかのタブをすべて閉じる」「すべてのタブを閉じる」「ファイルのパスをコピー」「ファイルの場所を開く」。閉じれるタブがない（何も書いていない「無題」タブ1つだけ）ときは、「タブを閉じる」などの閉じる系のメニューはグレーアウトし、× ボタンは表示しない。
  - リストファイル（CSV）など先頭が「BveTs」の BVE のファイルは確認なしで開く。画像・音・3D モデルなどは Windows で関連付けられたソフトで開き、exe などの実行ファイルや文字でないファイルはエディタで開かない。
  - エクスプローラーペイン設定ファイル（`.bveep`）の保存・復元・OS関連付け。
  - 「プログラムから開く」やエディタの exe へのドラッグで渡したファイル（.txt など）は、前回のタブを復元した後にエディタで開く（.bveep はエクスプローラーペインとして読む）。
  - エクスプローラーペインは、フォルダの中でファイルが増える・消える・名前が変わると自動で読み込み直す。開いていたフォルダ・選んでいた項目・スクロール位置はそのまま。名前の変更では使えない文字・予約名（CON など）を止め、exe・dll・sys などシステムにかかわるファイル（拡張子の一覧は system_extensions_list.md の「止める」側。FileExplorerPaine.cs の ProtectedExtensions）は、名前の変更・その拡張子への変更・貼り付け（フォルダなら中に1つでもあるとき）・名前を付けて保存で作ることができず、エディタで開くこともできない。
  - Windows・Program Files・Program Files (x86)・ProgramData と、ドライブ直下の $Recycle.Bin・PerfLogs は、フォルダとして開けず、中のファイルも開けない（エクスプローラーペインのツリーにも出さない）。
  - プロジェクト（`.bveproj`）を開くときに未保存のタブがあれば、先に保存するか聞く（キャンセルで開くのをやめる）。
  - クラッシュ時の作業自動復元機能およびタブ・ペイン状態の保存。
  - 終了時にタブごとのカーソルの位置（行・列）を記録し、次に開いたときにその位置に戻す（プロジェクト `.bveproj` も同じ）。「設定」➔「終了時のカーソル位置を記録する」でオン・オフ（初期値はオン）。

## 📦 発行（配る形にする）

Visual Studio の「発行」では、構文チェックのワーカー（BveMapParserWorker）が win-x64 用に作り直されずにエラーになるため、コマンドで発行する。

```
dotnet publish "H:\backup\d\users\kai\Document\project\BveMapEditor\BveMapEditor.csproj" -p:PublishProfile=FolderProfile
```

- 出力先: `bin\Release\net10.0-windows\publish\win-x64\`（ランタイムを含む形。エディタとワーカーの両方が入る）
- 配る前に、出力先に残っている `autosave.bveproj`（前に開いていたファイルのパスが入っている）と `settings.json` を消す
- Release ではデバッグシンボル（.pdb）を作らない設定（両方の csproj）。前の発行で残った .pdb は発行し直しても消えないので、出力先から消す

## 🚀 使い方

1. **ファイル・フォルダを開く**
   - メニューの `ファイル` ➔ `ファイルを開く` または `フォルダを開く` からプロジェクトを選択します。
2. **マップ編集 & エラー確認**
   - コード編集時、画面下部の「構文エラー一覧」に検出されたエラーがリアルタイム表示されます。
   - エラー項目をダブルクリックすると、該当する行・列へ直接ジャンプします。
3. **BVEでデバッグ実行**
   - メニューの `デバッグ` ➔ `BVEでデバッグ実行`（または `QuickMapViewerを実行`）を選択すると、BVE本体（QuickMapViewer）を起動できます（初回の実行ファイル指定ダイアログで `.exe` を登録）。
   - マップのファイルは渡さないので、試すシナリオ・マップは起動したソフトで選んでください。BVE は保存されたファイルを読むので、先にエディタで保存しておきます。

## 🛠 プロジェクト構成

2つのプロジェクトでできています。エディタ（画面）と、構文チェックをする別のプログラム（ワーカー）です。エディタはワーカーを起動して、名前付きパイプでやり取りします（入力が止まって 0.7 秒たつと、マップの本文と、タブで開いている保存前の内容を送り、エラーなどを受け取る）。

│   ├── BveMapEditor.csproj        # エディタのプロジェクト（ワーカーを参照。Release は .pdb を作らない）
│   │
│   │   ── 画面・全体 ──
│   ├── App.xaml / .cs             # 起動（渡されたファイル・.bveep の処理）・クラッシュログ・関連付けの登録

│   ├── Maps/                      # 試験用のサンプルシナリオ

│   ├── BveMapParserWorker/        # ワーカーのフォルダへのリンク（ビルドの対象からは外している）

└── BveMapParserWorker/            # ワーカー（構文チェックをする別のプログラム。画面なし）
    ├── BveMapParserWorker.csproj  # ワーカーのプロジェクト（出力先はエディタの bin。Release は .pdb を作らない）
    ├── Program.cs                 # 名前付きパイプでエディタとやり取りする（--worker --pipe 名前 --parent エディタの番号 で起動。

    ├── MapParser.cs               # 構文チェックの入口（字句解析 → 構文解析 → 意味のチェック。エラーの波線の範囲もここで決める）

    ├── BveSemanticCommandRules.cs # コマンドごとの引数の数・数値の引数かどうか
    ├── BveSyntaxProvider.cs       # コマンドの辞書（構文チェックと自動補完の両方の元。コマンドを足すときはここだけ直す）
    └── BveCompletionData.cs       # 自動補完の候補の形（ワーカー側）
